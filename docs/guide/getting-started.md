# Set up a CHO project

Choose the package that owns your entry point. You can add another package later when the application gains a second interface.

| Build | Install | First working example |
| --- | --- | --- |
| HTTP API | `@chojs/web` | [Serve a book as JSON](/web/quick-start) |
| Command-line tool | `@chojs/command` | [Print a shelf label](/command/quick-start) |
| Message consumer | `@chojs/message` | [Receive an inventory message](/message/quick-start) |

## Create a directory

```sh
mkdir library
cd library
```

## Install the package

The commands below set up the HTTP example. For a CLI or consumer, substitute the package from the table in the `jsr add` or `deno add` command.

::: code-group

```sh [Deno]
deno init
deno add jsr:@chojs/web
```

```sh [Node.js]
npm init -y
npm pkg set type=module
npx jsr add @chojs/web
npm install --save-dev tsx typescript @types/node
```

```sh [Bun]
bun init -y
bunx jsr add @chojs/web
```

:::

Each tutorial supplies its own `app.ts` and entry point. Use those contents for the named files, including any starter file generated by your runtime.

## Check the environment

For the HTTP tutorial, use a runtime with the global `URLPattern` API. Check from the same runtime that will start the server.

::: code-group

```sh [Deno]
deno eval 'console.log(typeof URLPattern)'
```

```sh [Node.js]
node -p 'typeof URLPattern'
```

```sh [Bun]
bun -e 'console.log(typeof URLPattern)'
```

:::

A result of `function` means the built-in router is available. For another runtime, use the [Hono adapter](/adapters/hono). CLI and in-memory message delivery work independently of the HTTP router.
